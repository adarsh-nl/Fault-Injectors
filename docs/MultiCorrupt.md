# MultiCorrupt fault injectors (exact)

Injectors ported from MultiCorrupt (Beemelmanns et al., arXiv:2402.11677;
github.com/ika-rwth-aachen/MultiCorrupt). The corruption math is MultiCorrupt's
**verbatim** code, isolated in three files and called unchanged:

- `_mc_image.py` - exact copy of MultiCorrupt `converter/img.py` (camera corruptions).
- `_mc_lidar.py` - exact extract of the fog / points / beams functions from
  `converter/lidar.py` (`ParameterSet`, `get_integral_dict`, `P_R_fog_hard`,
  `P_R_fog_soft`, `simulate_fog`, `pointsreducing`, `reduce_LiDAR_beamsV2`).
- `_mc_snow.py` - exact extract of the snow machinery from `converter/lidar.py`
  (16 functions: `compute_occupancy`, `snowfall_rate_to_rainfall_rate`,
  `ransac_polyfit`, `estimate_laser_parameters`, `process_single_channel`,
  `binary_angle_search`, `compute_occlusion_dict`,
  `tangent_angles_to_interval_angles`, `do_angles_intersect_particles`,
  `angles_to_lines`, `tangent_lines_to_tangent_angles`, `tangents_from_origin`,
  `distances_of_points_to_lines`, `get_occlusions`, `received_power`, `xsi`),
  which is Hahner et al.'s LiDAR snowfall simulation (CVPR 2022,
  github.com/SysCV/LiDAR_snow_sim) as adapted by MultiCorrupt.
- `fog_lookup_tables/` - the three precomputed integral tables `simulate_fog` needs.
- `snow_laser.yaml` - the HDL-64 sensor calibration the snow simulation models
  (copied from MultiCorrupt).
- `snowflake_sampling.py` - Hahner's verbatim `dart_throwing` particle sampler
  (plus `sekhon_srivastava`, `gunn_marshall`) with a thin seeded driver that
  generates the particle files MultiCorrupt consumes (see below).

The thin `*Injector` wrappers seed numpy for reproducibility, return uint8 for
images, and (for LiDAR fog and snow) optionally convert ego -> sensor -> ego around
the simulation. They do not alter any corruption algorithm.

## Severity (MultiCorrupt Table I)

| Fault | Modality | Level 1 / 2 / 3 |
|---|---|---|
| Brightness | camera | +0.5 / +0.6 / +0.7 in HSV V |
| Darkness | camera | Poisson-Gaussian s = 25 / 12 / 5 |
| Fog | camera + LiDAR | visibility 300 / 150 / 50 m |
| Snow | camera + LiDAR | 5 / 35 / 70 mm/h |
| Points reduction | LiDAR | drop 70 / 80 / 90 % |
| Beam reduction | LiDAR | keep 16 / 8 / 4 of 32 beams |

For LiDAR snow the severity levels map internally to (snowfall rate mm/h,
terminal velocity m/s) = (0.5, 1.2) / (2.5, 1.6) / (1.5, 0.4), i.e. airborne
occupancy ratios 1.16e-6 / 4.34e-6 / 1.04e-5. These pairs are hard-coded in
MultiCorrupt's `simulate_snow` and are reproduced exactly.

## What runs exactly on Griffin

Griffin `load_lidar` returns `(N,4)` = x, y, z, intensity (no ring column, no
semantic labels).

- **Camera brightness / darkness / fog / snow** - exact, run on any RGB image
  (vehicle-front and drone-bottom both work).
- **LiDAR fog** (`LidarFogInjector`) - exact, runs on `(N,4)`; uses only x,y,z and
  intensity plus the lookup tables. Attenuates intensity (Beer-Lambert) and adds
  fog-scatter points. Pass `T_lidar_to_ego` so beam ranges are measured from the
  sensor origin (the wrapper converts ego -> sensor -> ego; the physics is
  untouched).
- **LiDAR points reduction** (`PointsReductionInjector`) - exact, runs.
- **LiDAR snow** (`LidarSnowInjector`) - Hahner/MultiCorrupt physics verbatim, with
  two documented Griffin-derived inputs. See the dedicated section below.

## LiDAR snow on Griffin

MultiCorrupt's `simulate_snow` needs three nuScenes-specific things: an `(N,5)`
cloud with a ring/channel column, per-point lidarseg labels (to locate the ground
for the adaptive noise-floor fit), and pre-sampled snowflake particle files
`gunn_{rain_rate}_{occupancy}_{i}.npy` which are generated by Hahner's
LiDAR_snow_sim and are not distributed with MultiCorrupt. Griffin has none of
these, so:

1. **Particle files are generated, not approximated.** `snowflake_sampling.py`
   contains Hahner's verbatim `dart_throwing` sampler (Gunn-Marshall diameter
   distribution, non-overlapping disks in an 80 m plane). For each severity,
   `ensure_particle_files` samples the 64 per-channel files with independent
   deterministic seeds (42 + channel index) and the exact runtime filenames
   MultiCorrupt builds. Generation is a one-time cost of a few minutes per
   severity; files are cached under `src/fault_injectors/npy/` and are
   reproducible byte-for-byte from the code (they are deliberately not committed:
   about 97 MB of random floats).
2. **Ground mask (substitution A).** The lidarseg driveable/other-flat/sidewalk
   lookup is replaced by a geometric RANSAC ground-plane fit
   (`geometric_ground_mask` in `lidar_snow.py`): candidates in the lowest height
   band, plane z = a x + b y + c by consensus over random minimal samples, inliers
   within 15 cm. On CARLA/AirSim towns the ground is near-planar, so this is a
   faithful stand-in for what the noise-floor fit needs. `simulate_snow_griffin`
   in `_mc_snow.py` is MultiCorrupt's `simulate_snow` with exactly this one
   substitution, marked inline; every other line is unchanged.
3. **Channel column (substitution B).** The simulation models an HDL-64 sensor
   (`snow_laser.yaml`, 64 channels with per-channel focal-correction constants).
   Griffin points are assigned to those 64 channels by binning elevation angle
   into 64 equal bins (`elevation_channels`). The channel column only groups
   points and selects per-channel particle files / focal constants; per-point
   geometry is untouched.

Range domain: the pulse-power simulation discretizes each beam over a fixed
[0, 120] m window (hard-coded in MultiCorrupt's `process_single_channel`; this is
the HDL-64 sensor model's valid range). Griffin's simulated LiDAR returns points
to 200-300 m+, which fall outside that window. `LidarSnowInjector` restricts the
simulation to points within `SIM_MAX_RANGE` (118 m) and passes farther points
through unchanged (flagged 0); snow attenuation is negligible at those ranges
anyway. This is a wrapper-level domain restriction, not a change to the physics.

Wrapper-level I/O handling (documented, non-algorithmic): intensities with
maximum <= 1.5 (CARLA convention) are scaled to the 0-255 range the pipeline
assumes and scaled back afterwards; if `T_lidar_to_ego` is given, points are
converted ego -> sensor for the simulation and back for the output.

Output contract: `(M,4)` float32 with M <= N (returns below the adaptive noise
floor are removed). `last_flags` gives the per-output-point status (0 unchanged,
1 attenuated, 2 snow scatter); `last_stats` is `(num_attenuated, num_removed,
avg_intensity_diff)`; `last_ground_fraction` reports the geometric ground share.

Validation on a synthetic 80 k-point ground+objects cloud: severity 1/3 produced
4 797 / 6 976 snow-scatter points (monotone in occupancy, as expected), tens of
thousands of attenuated and noise-floor-removed returns, and two identical runs
are byte-identical (seeded shuffle, seeded RANSAC, fixed particle files).
Runtime is roughly 1-3 minutes per severity per frame (per-point occlusion tests
inherited from upstream).

## What MultiCorrupt's exact code cannot do on Griffin

- **LiDAR beam reduction** - `reduce_LiDAR_beamsV2` selects scan lines by an integer
  ring index at column 4, and its allowed-beam lists are specific to a 32-beam
  sensor. Griffin is `(N,4)`/80-beam, so `BeamReductionInjector` raises by design
  (it will not misread intensity as a ring). Use `BeamReductionInjectorGriffin`
  (elevation-binning, keeps 40/20/10 of 80 beams) for a runnable path, or supply a
  genuine 32-beam ring column to use the exact function.
- **LiDAR snow with nuScenes semantics** - the lidarseg ground lookup itself cannot
  run on Griffin; the geometric substitution above is the documented replacement.

## Dependencies

    pip install scikit-image opencv-python scipy pyyaml

scikit-image and OpenCV serve the camera code; SciPy serves LiDAR fog
(integral tables) and snow (speed of light constant, linregress); PyYAML reads
`snow_laser.yaml`.

## Environment compatibility patches (all marked inline, semantics-preserving)

- `_mc_image.py`: `np.float_` was removed in NumPy 2.0; shimmed to `np.float64`
  (an exact alias).
- `_mc_lidar.py`: stdlib `pickle` instead of `pickle5` (a backport for
  Python < 3.8; protocol-compatible on 3.8+).
- `_mc_snow.py` (`estimate_laser_parameters`): upstream indexed `xedges` with a
  list containing an array; legacy NumPy treated that as tuple indexing (1-D
  result), NumPy 2.x treats it as advanced indexing (2-D result), which breaks the
  noise-floor `linregress` fit. The tuple form used computes identical bin
  midpoints. The original lines are kept in an adjacent comment.

## Install location

Place `fog_lookup_tables/`, `snow_laser.yaml` and (generated) `npy/` next to
`_mc_lidar.py` / `_mc_snow.py` inside `src/fault_injectors/` - both resolve data
relative to the module file.
